Processo 1: Registro de Pedidos pelos Vendedores

Requisito 1: O sistema tem que deixar o vendedor montar o pedido no computador ou celular, marcando os produtos que o cliente escolheu e a quantidade.
Fonte 1: Conversa rápida com os vendedores do telefone e da rua. Fonte humana, nível operacional, classe de usuário vendedor.
Fonte 2: Papéis e blocos de anotações que os vendedores usam hoje para anotar as vendas. Fonte não humana, categoria documentação.

Requisito 2: O sistema devia calcular o valor final sozinho, somando tudo e aplicando algum desconto se o vendedor tiver permissão para dar.
Fonte 1: Papo com o supervisor de vendas. Fonte humana, nível tático, classe de usuário gestor de vendas.
Fonte 2: Uma tabela em PDF com os preços e limites de desconto que eles usam atualmente. Fonte não humana, categoria documentação.

Requisito 3: O sistema precisa mandar uma confirmação da compra para o cliente, tipo um comprovante no WhatsApp ou no e-mail.
Fonte 1: Ideia tirada de outros aplicativos de compras que já fazem isso. Fonte não humana, categoria concorrência.
Fonte 2: Entrevista com um vendedor antigo da casa. Fonte humana, nível operacional, classe de usuário vendedor.

Processo 2: Gestão de Produtos pelo Administrador

Requisito 4: O administrador precisa de um lugar no sistema para cadastrar as coisas novas que chegam para vender, colocando nome, foto e preço.
Fonte 1: Conversa com o responsável por cuidar do catálogo. Fonte humana, nível tático, classe de usuário administrador.
Fonte 2: Uma planilha de Excel antiga onde eles guardam a lista de produtos hoje em dia. Fonte não humana, categoria sistema legado.

Requisito 5: Se um produto parar de ser vendido, o sistema devia permitir esconder ele da lista sem apagar o histórico do que já foi vendido no passado.
Fonte 1: Reunião informal com o dono da empresa. Fonte humana, nível estratégico, classe de usuário gestor executivo.
Fonte 2: Perguntas feitas para o administrador do sistema atual. Fonte humana, nível tático, classe de usuário administrador.

Requisito 6: O sistema devia avisar ou marcar quem foi que mudou o preço de um produto ou quem excluiu algum item do sistema.
Fonte 1: Conversa com o pessoal que cuida da parte de TI da empresa. Fonte humana, nível tático, classe de usuário gestor de TI.
Fonte 2: Regras básicas da empresa escritas num documento interno. Fonte não humana, categoria documentação.

Processo 3: Controle de Estoque pelo Pessoal do Galpão

Requisito 7: Toda vez que um vendedor fechar um pedido, o sistema tinha que descontar sozinho aquela quantidade do total de produtos guardados.
Fonte 1: Bate-papo com o pessoal que trabalha tirando as caixas das prateleiras. Fonte humana, nível operacional, classe de usuário operador de estoque.
Fonte 2: Anotações em cadernos que eles usam no galpão para conferir o que sai. Fonte não humana, categoria documentação.

Requisito 8: Quando chegar caixa nova da fábrica, o pessoal do estoque precisa conseguir dar entrada no sistema digitando o código da nota ou usando um leitor de código de barras.
Fonte 1: Entrevista com o encarregado do depósito. Fonte humana, nível tático, classe de usuário supervisor de estoque.
Fonte 2: O programa antigo que eles usavam só para controlar as caixas que entravam. Fonte não humana, categoria sistema legado.

Requisito 9: O sistema podia dar um aviso na tela quando algum produto estivesse quase acabando no estoque para dar tempo de pedir mais.
Fonte 1: Conversa com o responsável pelas compras da empresa. Fonte humana, nível tático, classe de usuário gestor de estoque.
Fonte 2: Folha impressa com a lista dos produtos que mais vendem no mês. Fonte não humana, categoria documentação.
